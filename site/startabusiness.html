æQR is one discovery layer across many resources without making every resource public. A QR is an address into the constellation — not permission to access or execute. Integrity is proven by decoding the artifact back. Authority stays with the human.

What this actually is

Not a landing page. Two working systems joined by one question: how does an agent find a resource, prove it is real, and know whether it is allowed to act on it?

Two rules carry the weight

// 1  A QR that has not been decoded back is not a QR — it is a picture of one.
    The rune magic æ: encodes fine and fails on scan (pyzbar mangles the
    UTF-8 bytes). A single-decoder check passes exactly the artifact that
    fails in the field. The transport magic is ASCII (ae:); the
    æ identity lives in the payload, not the wire.

// 2  Scanning never grants execution. resolve, read, verify are open.
    publish, execute, merge require an explicit, scoped Capability.
    Planning a repair ("ready") is not proving it ("verified").

The stack

The envelope — 8 typed payloads

# one wire format for everything that crosses a boundary
ae:1:<type>:<base64url(json)>

  key · secret · contract · capability · route · handoff · identity · manifest

# the type is IN the address, so a decoder can refuse what it cannot route

The gate — 9 checks, 3 of them advisory

refuse-capable   roundtrip · cross_decoder · charset · payload_match
                 quiet-zone-presence · decodability
advisory         module_size · quiet_zone · contrast

# A check that refuses an artifact both decoders read is a bug, not a gate.
# module_size measured the finder ring along the top edge; on a rotated code
# that line crosses modules diagonally and reported a 177-module side for a
# real 25. If both decoders read it back exactly, it IS scannable — and a
# proxy's opinion of its module pitch is irrelevant.

The registry

One registry drives navigation, QR links, and the sitemap. An entry is an address and a scope — never a grant.

routeHTTPS URL, or ae://local/… for local/private
verifiedhas a real check proven this entry resolves?
evidencepointer to the proof, or null

Invariants — enforced, not documented

· every required field is present
· scope is one of the four
· ids are unique
· public scope  ⇒  the route is an HTTPS URL
· local  scope  ⇒  the route is an ae://local/ scheme address

The gate

SPEC → RENDER → SUPERVISE → receipt or refuse. Two independent decoders must agree, because the failure this catches is the silent one.

The failure class it exists for

The rune magic æ: — an in-memory round trip passes it. Only a real
decoder catches it:

  ✗ charset        non-ASCII 'æ' at 0 — a real decoder will mangle it
  ✗ cross_decoder  cv2 and pyzbar disagree on the bytes
